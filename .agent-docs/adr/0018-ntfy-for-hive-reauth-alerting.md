# ntfy.sh as hive-app's re-auth alert channel

Every existing job in this repo signals failure passively, through `job_run` rows a Grafana staleness panel surfaces on demand — nobody is notified proactively; you have to look at the dashboard. hive-app's Hive client introduces one failure mode that pattern doesn't fit: if Cognito forgets its remembered device, recovery needs a live SMS 2FA code, something a headless service cannot supply itself (see `.agent-docs/research/hive-api-access-approach.md`). A dashboard staleness panel that nobody's looking at leaves the heating client silently dead until someone happens to check.

"Cognito forgets its remembered device" is the canonical case, but the alert covers every apyhiveapi failure that likewise needs a live re-login (see `_REAUTH_REQUIRED_EXCEPTIONS` in `hive_client.py`), and fires at container startup as well as from the heating poll, de-duplicated across both by a single shared `ReauthAlert`.

We chose ntfy.sh — a single HTTP POST to a topic URL, no account/SMTP setup — as the first proactive/push alert channel this repo has, scoped narrowly to only this one failure case (not a general-purpose alerting mechanism for every job failure; those stay on the existing `job_run`/dashboard pattern). This is a real precedent: it's the first time this codebase reaches outside its own dashboard to push a notification, and future features reaching for "alert me about X" should reuse this channel rather than each inventing their own.

## Amendment: two notifications, a secret topic, and a way to act on the alert

- **Exactly two notifications**, both about Hive auth: *re-authentication required* and *authentication recovered*. "Recovered" is sent only after a "required" alert was actually delivered, so it never fires on routine successful polls. Poll failures, startup or config errors, and other apps' failures are still deliberately not notifications.
- **Format.** Title `<app>: <short event>`, plain-sentence body without a timestamp (ntfy adds one), `high` priority when action is needed and `default` for recovery, one status emoji tag, and a `Click` link only when it helps. "Required" links to `deployments/hive-app/REAUTH_RUNBOOK.md` on `main`.
- **Topic.** ntfy.sh topics are public, so the topic is `home-monitoring-hive-auth-ntfy-<guid-no-dashes>` and the GUID is the only secret. The full `ntfy.topic_url` lives only in the Pi's `config.yml`; the repo carries a placeholder and the format.
- **Recovery exists.** The original alert told the operator an SMS login was needed but nothing could perform one. `python -m hive_app.login` (run via `docker exec -it hive-app`) now completes the SMS challenge, registers the device and writes `hive_auth_state.json`; the runbook documents it. This reverses the earlier decision to leave interactive code entry out of scope.
