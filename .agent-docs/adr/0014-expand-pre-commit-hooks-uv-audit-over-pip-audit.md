# Expand pre-commit hooks (uv-audit, actionlint, validate-pyproject, shellcheck); use uv-audit rather than pip-audit, and skip pyproject-fmt

> **Note**: `.github/actions/code-quality-checks/action.yml` was later inlined into the `checks` job of `.github/workflows/ci.yml` (spec `chore-ci-speedup`), which now also has a shell script for shellcheck to check.

Building on the hook set from [#375](https://github.com/mholubinka1/home-monitoring/issues/375), we added four hooks to `.pre-commit-config.yaml` and mirrored each as a direct step in `.github/actions/code-quality-checks/action.yml` (CI runs the checks itself, not `pre-commit`, so a hook with no CI step is `--no-verify`-bypassable and invisible on PRs): `uv-audit` from `astral-sh/uv-pre-commit` (already pinned here for `uv-lock`) for dependency vulnerability auditing, `validate-pyproject` for `pyproject.toml` schema validation, `actionlint` for `.github/workflows`, and `shellcheck` for shell scripts. `shellcheck` matches nothing today — the tree has no `.sh` files — and is in place for when one appears.

`pip-audit` was the original request for the vulnerability audit, but it cannot read `uv.lock`: wiring it in means running `uv export` to a `requirements.txt` and auditing that. [ADR-0004](0004-poetry-to-uv-migration.md) deliberately deleted `requirements.txt` and pointed Dependabot at `uv.lock` directly, so reintroducing a committed export — even a generated one — would reverse that decision for no benefit `uv-audit` doesn't already provide. `uv audit` reads the lockfile directly, audits the full locked set (including dev groups) rather than a `--no-dev` export, and its hook only fires when `uv.lock`/`pyproject.toml` change, so it adds no per-commit network call. It is still marked experimental by `uv`; the CI `setup-uv` step is pinned to the same uv version as the hook (`0.11.33`) so both sides run identical behaviour, and `uv-audit` sits alongside — not replacing — Dependabot's daily scan.

`pyproject-fmt` was in the request and was left out. It unconditionally alphabetises every string array — including this repo's `[tool.pylint]` `disable` list, whose entries each carry a preceding comment explaining why that check is disabled — and collapses `[tool.pylint.main|design|"messages control"]` into dotted keys under one table. Both reorderings detach the rationale comments from the entries they document, and the formatter has no option to disable either. `validate-pyproject` covers the correctness half of what `pyproject-fmt` offered without touching layout.
